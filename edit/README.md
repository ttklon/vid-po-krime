# Учебная монтажная версия ППНМ

## Статус и исправление

Ранний вывод об отсутствии манекена был сделан по слишком редким кадрам и исправлен. При плотном обзоре 593 кадров по всей длительности восьми исходников найден фрагмент с манекеном в IMG_4682.MOV около 04:24–04:54. Он сохранён в плане. Промежуточный план с титром об отсутствии этого эпизода не экспортировался.

Текущий план: `edit/plan.json`. Целевая длительность — **833,4 секунды (13:53,4)**, 1920×1080, 30 кадров/с, H.264 CRF 18, AAC stereo 48 кГц / 192 кбит/с. Использованы семь из восьми роликов; только короткий неудачный IMG_4690 не включён. Никакие исходники из архива не удалены.

## Порядок

1. Короткий начальный титр с обозначением учебной монтажной версии.
2. Осторожное пояснение: полнота разъяснения прав по записи не подтверждена. Не утверждается, что в действительности права никому не разъяснялись.
3. Начало действия — IMG_4691.
4. Представление участников — IMG_4692.
5. Отказ от защитника и сопровождение — IMG_4691.
6. Техника и специалист — IMG_4693.
7. Имеющийся блок прав, рассказ, вопросы и объявление выезда — IMG_4698.
8. Прибытие, весь подъём в подъезде, вход, рассказ и найденный фрагмент с манекеном — IMG_4682.
9. Объявление об ознакомлении с записью — IMG_4685.
10. Ответы участников и завершение — IMG_4686.
11. Короткий заключительный титр.

Это сюжетная последовательность учебной постановки, а не реальный порядок съёмки. Монтаж не удостоверяет непрерывность следственного действия. Произнесённые персонажами слова «без монтажа» относятся к сценарию; итоговый файл прямо обозначен монтажной версией.

Работа с папкой у двери видна. Подписание документов всеми участниками после демонстрации пока отдельно не подтверждено; иные кадры не объявляются таким подписанием. Не выполнена ручная вычитка всех тихих реплик и имён. Черновые автоматические SRT в фильм не вшиваются.

## Экспорт, просмотр и автоматическая резервная копия

```sh
python3 -m venv .venv
.venv/bin/pip install -r edit/requirements.txt
.venv/bin/python tools/render_film.py
```

Сервер слушает `0.0.0.0:8081` (можно задать `FILM_PORT`). Страница без ключа показывает реальный ход FFmpeg, затем видео и ссылку скачивания. Поддерживаются HTTP Range для перемотки. Сервер намеренно публичный, как согласованная пользователем открытая загрузка: не передавайте ссылку посторонним.

Перед экспортом SHA-256 исходников сверяется с сохранёнными манифестами. Если локальный исходник утрачен, он собирается из Git-частей. Из каждого выбранного интервала берутся его собственные видео и звук — чужие слова, сгенерированные кадры, клонирование голоса, оптическая интерполяция и подмена реплик не используются. Целые смысловые блоки не ускоряются. На границах звука применяется лишь 15 мс fade для устранения щелчков.

HLG / BT.2020 преобразуется в SDR / BT.709 с линейной обработкой и Hable tone mapping. Звук нормализуется двухпроходным loudnorm к -16 LUFS / -1,5 dBTP (с ограничениями фильтра при большом динамическом диапазоне). Имена и номера из ненадёжного распознавания не подставляются в речь.

Промежуточные файлы и журнал: `.cache/film-render/`. Готовые сегменты имеют контрольные отметки; при неизменном плане и коде повторный запуск их использует. Итог: `.cache/exports/ppnm_1080p_educational.mp4`.

После сборки весь результат декодируется по видео и аудио с `-xerror`; проверяются формат 1080p H.264, длительность и отсутствие геометок в метаданных контейнера. Только затем на странице открывается просмотр и скачивание. Результаты и SHA-256 — `.cache/film-render/export-result.json`; точная временная карта — `.cache/film-render/edit-ledger.json`.

После технической проверки **отдельно** вызывается локальный обработчик загрузки `http://127.0.0.1:8080`: итог передаётся ему частями по 4 МиБ, а тот делает коммиты Git-частей и push. Для этого должен продолжать работать согласованный сервер `UPLOAD_OPEN_ACCESS=1 python3 upload_server.py`. Зелёный статус резервной копии появляется только после его подтверждения. Ошибка резервного копирования не скрывает готовый MP4, но означает, что сохранение в GitHub не завершено. У текущей открытой сессии лимиты 16 файлов / 3 ГиБ; превышение отображается как ошибка, не обходится.

Локальный диск временный. Скачайте итог после готовности; до подтверждения GitHub храните оригиналы. Для бессрочного восстановления из Git используйте `restore_video.py` и соответствующий манифест итогового MP4 в `videos/`.
